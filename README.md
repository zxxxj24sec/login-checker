# login-checker 登录验证工具

携带账号密码发起登录请求，通过「登录前后内容差异」判断是否登录成功。支持单条检测和文件批量检测，批量结果按根域名自动写入「成功」和「复核」两类文档。

## 使用方法

### 批量检测（最常用）

```bash
python login_request.py --file accounts.txt --insecure
```

- 文件 `accounts.txt` 每行一条 `url:username:password`，冒号分隔；`#` 开头为注释，空行忽略
- **建议始终加 `--insecure`**：跳过 SSL 证书校验并放宽加密策略，避免高校/机构站点大量证书错误导致连不上
- 结果按根域名写入两类文档：成功 → `<根域名>.txt`；**需要验证码的站点失败** → `<根域名>_captcha.txt` 供人工复核。**失败且不需要验证码的直接丢弃、不落盘**
- 默认 20 并发，逐条实时输出进度，最后给汇总

### 指定根域名过滤

文件里混入无关站点时，用 `--domain` 只检测目标根域名，其余加载阶段直接丢弃、不发起请求：

```bash
python login_request.py --file accounts.txt --insecure --domain swu.edu.cn
# 多个根域名逗号分隔
python login_request.py --file accounts.txt --insecure --domain swu.edu.cn,ncepu.edu.cn
```

支持子域名匹配：`--domain swu.edu.cn` 会保留 `mail.swu.edu.cn` 等子域名，丢弃其他根域名。

### 单条检测

```bash
python login_request.py --url <登录地址> -u <账号> -p <密码>
# 指定登录后页面应出现的文字，判定更精确
python login_request.py --url <登录地址> -u <账号> -p <密码> --check-contains "我的订单"
```

### 大批量（上千条）推荐参数

```bash
python login_request.py --file accounts.txt --insecure \
    --timeout 3 --concurrency 32 --hard-timeout 15 --max-time 1800
```

### 常用参数

| 参数 | 说明 |
|------|------|
| `--file` | 批量检测文件，每行 `url:username:password` |
| `--domain` | 只检测指定根域名下的条目，可传多个（逗号分隔） |
| `--insecure` | 跳过 SSL 证书校验并放宽加密策略（推荐跑高校/机构时加） |
| `--url` / `-u` / `-p` | 单条模式：登录地址 / 账号 / 密码 |
| `--check-contains` | 登录后页面应出现的文字，出现即成功 |
| `--success-contains` | 登录响应应出现的文字，命中即成功 |
| `--fail-contains` | 登录响应应出现的文字，命中即失败 |
| `--user-field` / `--pass-field` | 用户名字段名（默认 `username`）/ 密码字段名（默认 `password`） |
| `--json` | 以 JSON 格式提交（默认表单） |
| `--no-check` | 关闭行为验证，只看登录响应 |
| `--auto-fields` / `--no-auto-fields` | 自动抽取登录页隐藏字段（默认开启） |
| `--check-url` | 验证页地址，默认用登录页本身 |
| `--concurrency` | 批量并发数，默认 20 |
| `--timeout` | 单次请求超时秒数，默认 8 |
| `--hard-timeout` | 单条任务硬超时，超时直接丢弃 |
| `--max-time` | 整轮批量总时限，到点输出已完成结果 |
| `--read-timeout` | 读取单个响应体的总时间预算 |
| `--dns-timeout` | DNS 解析超时，默认 3 秒 |
| `--max-bytes` | 单个响应体最多读取字节数，默认 512KB |
| `--proxy` / `--no-env-proxy` | 指定代理 / 忽略环境变量代理直连 |
| `--output-dir` | 结果文档输出目录，默认脚本同目录 |
| `-v` / `--verbose` | 打印详细诊断信息 |

## 判断逻辑

判定按**优先级从高到低**，命中即出结果：

| 优先级 | 条件 | 结论 |
|--------|------|------|
| 1 | 显式 `--fail-contains` 命中 | 失败 |
| 2 | 接口明确返回认证失败（JSON 非 0 业务码 / `success=false` / HTTP 401·403·其他 4xx·5xx） | 失败 |
| 3 | 响应含登录失败特征词（`密码错误` / `认证失败` / `login failed` …） | 失败 |
| 4 | 显式 `--success-contains` 命中 | 成功 |
| 5 | 被重定向回登录页 | 失败 |
| 6 | JS 跳转到 CAS / 统一身份认证登录页（`caslogin`/`authserver`/`passport`）**且无会话凭据** | 失败 |
| 7 | 有强会话凭据 **且** 实质跳转到登录后页面 | 成功 |
| 8 | 有强会话凭据 **且** 脚本跳转（非静态、非 CAS） | 成功 |
| 9 | 有强会话凭据（`auth_token` / `access_token` / `jwt` …，凭据本身即证据） | 成功 |
| 10 | 登录表单消失 **且** 出现登录后元素（`退出登录` / `我的账户` …）<br>*须同时满足：匿名页确实有表单、且该元素匿名页没有* | 成功 |
| 11 | 表单消失 + 出现登录后元素，但**拿不到匿名基线** | 异常 |
| 12 | 响应内容仍是登录表单 | 失败 |
| 13 | 实质跳转到登录后页面（`/home` / `/dashboard` …，此时无凭据） | 成功 |
| 14 | 跳转目标含 `login` / `error` / `fail` / CAS 登录页 | 失败 |
| 15 | 跳转，但**匿名访问时该跳转同样存在**（站点固有静态跳转） | 失败 |
| 16 | 跳转，但**无会话凭据**、无法确认是登录后页面 | 失败 |
| 17 | 仅收到**通用会话 Cookie**（`JSESSIONID` / `PHPSESSID` …，登录失败也会下发） | 失败 |
| 18 | HTTP 200 但**无任何成功/失败证据** | 失败 |

以上是**第一步「登录响应判定」**（`judge_login_response`）。当能拿到匿名基线且有验证页时，会进入**第二步「二次仲裁」**（`judge_protected_page`），用登录前后页面内容对比**覆盖第一步结论**，其内部优先级：

| 优先级 | 条件 | 结论 |
|--------|------|------|
| 1 | 登录后访问仍被拦截（登录墙 / 401·403 / 仍返回登录表单） | 失败 |
| 2 | 指定了 `--check-contains`：页面出现 | 成功 |
| 3 | 指定了 `--check-contains`：页面未出现 | 失败 |
| 4 | 登录响应已判失败（接口认证失败 / 失败特征词），页面特征不翻案 | 失败 |
| 5 | 表单消失 + 出现登录后元素（需匿名基线：匿名页有表单、元素匿名页没有） | 成功 |
| 6 | 登录响应已给出成功证据（凭据 / 跳转） | 成功 |
| 7 | 兜底：登录前后内容相似度 ≤80%（变化明显） | 成功 |
| 8 | 兜底：登录前后内容相似度 >80%（内容未变） | 异常 |

**说明：**

- **「异常」仅剩 2 种**：第 11 条（表单消失 + 登录后元素但拿不到匿名基线）和二次仲裁第 8 条（相似度 >80%），均保守不下结论、留待人工复核——其余「证据不足」的模糊情况（静态跳转 / 无凭据跳转 / 仅通用 Cookie / 无任何证据）已一律判**失败**。
- **验证码不再提前拦截**：带验证码的站点照常走判定流程，登录成功则进「成功」，否则归入「复核」文档（不少站点验证码弱校验/可空，仍能登录）。
- **验证码降级**：判定为「失败」时，若登录页本身含验证码（表单里有验证码输入框，或有验证码图片），则不判失败、改归入「复核」——验证码挡着无法自动完成，不能据此认定密码错误。**不需要验证码的站点失败则直接丢弃、不落盘、不进任何文档**。
- **「强会话凭据」≠ 通用会话 Cookie**，且必须是「本次登录新签发」的：`JSESSIONID` 等通用标识匿名就下发、不算；只有 `auth_token`/`access_token`/`jwt` 这类登录后才签发的才算；匿名基线里已存在的同名 Cookie 也不算。
- 失败证据（接口失败 / 失败特征词）**优先于**页面特征：接口说失败，即使页面碰巧出现「退出登录」也判失败。
- JS 跳转（`window.location` 等）**不单独作为成功证据**：站点固有静态跳转、无凭据跳转都会用匿名基线排除。
- 「跳转」只认实质跳转：`http→https`、加/去 `www`、去默认端口这类 URL 规范化不算。
